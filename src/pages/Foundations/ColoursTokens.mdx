## Token reference

The token reference connects DiamondDS semantic colour roles to CSS variables
and MUI palette roles. Use semantic tokens and MUI palette roles in components,
and avoid hardcoded hex values.

### Intent and brand roles

Intent and brand colours follow a shared structure. In the patterns below,
`[token]` stands for a role such as `primary` or `danger`, and `[role]` for its
MUI palette name.

<Callout>
  Token names and MUI role names usually match. The exception is that DiamondDS
  uses `danger` tokens internally, which map to the MUI `error` palette role.
  The MUI names `light` and `dark` mean accent and emphasis, not lighter and
  darker.
</Callout>

### Neutral roles

Neutral tokens create the structure of the interface. They should be the default
choice for layout, surfaces, borders, text and dense scientific workflows.
