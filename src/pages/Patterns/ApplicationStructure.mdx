# Application Structure

<Lead>
  Skeleton diagrams of the core regions of a Diamond application, such as
  navigation, workspace controls, content and auxiliary drawers, combined into
  reusable layouts. The patterns cover desktop screens.
</Lead>

The patterns are examples, not fixed templates. Mix and match regions to suit
your application, and start with the simplest pattern that fits. Add regions
only when the task needs them.

<Callout title="Work in progress">
  Pattern names are provisional. Some regions have no SciReactUI component yet,
  and the Components column says which.
</Callout>

it as one block of content. Patterns 7 and 8 split it into example parts, E1 to

Otherwise compose from MUI.

### 6. Temporary side drawer

Desktop shell with an on-demand side drawer over the workspace and a global
status footer. Selecting a row in a table view can open the drawer with that
row’s details. The drawer can hold different kinds of content, such as a form or
tabbed views. Make it wider for larger content, up to about 75% of the width.

The workspace behind the drawer can behave in two ways:

- Blocked: clicking outside closes the drawer. This is the default for a
  `temporary` `Drawer`.
- Still usable: selecting another row swaps the drawer’s content. In MUI, set
  `hideBackdrop`, `disableEnforceFocus`, `disableAutoFocus` and
  `disableScrollLock`, and `pointerEvents: "none"` on the drawer’s root, and keep
  the drawer itself interactive. There is no single prop for it.

Review the requirements before choosing “still usable”. A `temporary` `Drawer`
is a modal, so it can still hide the rest of the page from screen readers and
close on Escape. Test keyboard and screen-reader access to the workspace. If it
cannot be reached that way, keep the workspace blocked.

The diagram alternates between the two. With the default backdrop the whole
screen is dimmed and blocked. With `hideBackdrop` nothing is dimmed, and the
workspace stays usable.
