# Introduction

<Lead>
  The Diamond Design System is a shared foundation for building clear,
  consistent and reliable scientific interfaces across Diamond Light Source.
</Lead>

It supports the tools used for data acquisition, analysis and operations, so
that interfaces behave in clear, coherent and predictable ways across scientific
workflows and applications.

The React implementation is
[SciReactUI](https://github.com/DiamondLightSource/sci-react-ui). It provides
the MUI theme, design tokens and reusable components. This site explains why,
when and how to use them.

## What it helps us do

- Create clearer, more predictable scientific interfaces.
- Bring consistency across tools and beamlines.
- Reduce cognitive load in complex workflows.
- Speed up development with reusable components.
- Make sure new tools start coherent and stay aligned.

## Why we need a design system

Diamond runs a growing ecosystem of tools across beamlines, data acquisition,
analysis and scientific support. Many of them evolved independently, with
different patterns, behaviours and visual languages.

Diamond II is a clear moment to modernise these interfaces around clarity,
safety, efficiency and consistency.

- **User-centred interfaces:** built around real user needs, which reduces
  friction, errors and workarounds.
- **Unify systems:** shared patterns reduce inconsistency across tools and
  workflows.
- **Modernise for Diamond II:** new beamlines and workflows give us a chance to
  redesign interfaces for clarity, safety and efficiency.
- **Reduce cognitive load:** familiar, intuitive interfaces cut training time
  and mental effort when moving between systems.
- **Improve collaboration:** shared standards create a common language between
  developers, scientists, designers and stakeholders.
- **Accelerate development:** reusable components and patterns reduce
  duplication and keep design and engineering aligned.
- **Future-proof our ecosystem:** every new tool, feature or beamline interface
  can start from a coherent foundation.

## What makes scientific interfaces different

- **Time is scarce:** beamline access is limited, and interruptions are costly.
- **Experiments are stateful:** the interface must make system state, progress
  and risk clear.
- **Users may be visiting:** scientists often need to become productive quickly,
  under pressure.
- **High-density data is normal:** tables, logs, dashboards, plots and
  configuration views are core to the experience.
- **Actions can be high consequence:** controls, destructive actions and state
  changes need clear signifiers and recovery paths.

## Principles

- Clarity over decoration.
- Predictability over novelty.
- Semantic structure over one-off styling.
- Accessibility and operational confidence.
- Reusable patterns over local solutions.
